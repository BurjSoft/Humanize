# Humanize Rule

For every proposal, cover letter, CV, resume, professional summary, outreach message and job-application screening answer:

1. Read and apply the installed `humanize` skill before finalizing. Resolve its current SKILL.md through the host's available skills catalog (it may appear as `humanize:humanize` when installed as a plugin). When working in this repository without an installed copy, use the bundled `skills/humanize/SKILL.md` relative to this repository root. If neither is available, report the missing skill rather than claiming it was applied. Do not claim it was applied without actually reading it.
2. Use the user's verified resumes, project history, corrections and previously confirmed answers as the only source of facts. Never invent clients, work, technologies, outcomes, years or metrics. Honor instructions to include or exclude named projects.
3. Edit for a natural personal voice: cut redundant setup, robotic repetition, stock openers, inflated claims, unnecessary em dashes, buzzwords and uniform sentences. Keep useful technical detail. Do not add errors, fake anecdotes or slang to influence detectors.
4. Answer screening questions directly. Keep eligibility, legal and location facts. Preserve ATS keywords and documented metrics in resumes.
5. AI-detector results are advisory and only count if a detector actually ran. Never invent scores or promise that text will avoid being flagged.
6. Recheck every revision against the source and the reader's question. Deliver the polished text without process commentary unless asked.

For proposals, decide fit first (eligibility, required skills, deal-breakers), then draft, then humanize, then re-verify the opening lines, client specificity and the truth of every claim.
